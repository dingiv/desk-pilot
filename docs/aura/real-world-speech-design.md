## 1. 停顿碎片化 🔴 已解决

**现象**："帮我把…（停 1.5s）…会议文件…（停 1.2s）…改成 markdown" → VAD 每停顿切 EOS → 碎片段。

**根因**：VAD 切段灵敏度与"什么算一句话"混为一谈。`min_silence` 必须保持小（1s）保响应，
代价是长句被强切。

**方案（边界范式）**：`min_silence`（切段）与 `merge_gap`（合并窗口上界）**解耦**——
- 停顿 ≥min_silence → EOS 切段，段级 batch + `Batch` 事件（低阈值保响应）；
- 段间静音 < merge_gap → 并入同一 `VadWindow`（窗口级 batch 重跑出权威文本）；
  ≥ merge_gap → 窗口定稿 `WindowEdge`。
- merge_gap=0 → 每段独窗；单段窗口免重跑（复用段级 batch）。
- **段边界损失**（句首/尾掉字）：`edge_margin`（0.3s）扩展段头/段尾真实音频。

**验证**：停 3s → 1 段 final；停 6s → 2 段。

## 2. 语气词污染 🟡 P1

ASR 保持忠实转写（不该去语气词）；去口语是 **Stage2** 职责。机制（few-shot 示例 + OUTPUT
"去口语"指令）都在 prompt.rs，但**默认注释**——启用前需重验 Qwen2.5-3B 无指令下的口语清洁度
（Qwen3-ASR 批式转写较干净，可能不需要该规则）。

## 3. 同音歧义 🟡 P1

ASR 无法区分音同字（"计分起" vs "计分器"），需上下文 + 语义。处理层：Stage2（纠偏）+
Stage3（热词/纠偏反馈）。
- **用户纠偏**（最可靠，已实现）：POST /api/correct → Stage2 权威示例。
- **热词**：烘进 Stage1 流式 recognizer（beam bias）；Stage2 prompt 热词块默认注释
  （小模型遵循不佳）。
- **模型上限**：Qwen2.5-3B 对部分中文同音字能修（蛇声→蛇身 ✅），部分不能（计分起→
  计分器 时有时无）。7B+ 会改善。

## 4. 口误自纠 🟢 设计完

用户说"帮我用 rost… 不对… Rust 写个游戏"。**模式匹配**（正则 `…不对/不是/应该是…`）
去掉纠正前内容，零 LLM 开销。实现：calibrator.rs `calibrate_window` 前预处理。

## 5. 中英混排格式 🟡 部分解决

OUTPUT 指令"英文单词前后加空格"已有；Qwen2.5-3B 部分通过。备选：正则补
`([一-龥])([a-zA-Z]) → $1 $2`。

## 6. 断句与标点 🟡 部分解决

Stage2 核心职责（OUTPUT 指令"加标点"）。短句 ✅，长句断句位置不稳定——3B 语义能力上限，
7B+ 改善。

## 7. 连读与吞音 🟢 P2

ASR 声学模型能力限制。**Qwen3-ASR 比 SenseVoice 英文连读好**（chief→chieftain 差异消失）；
Stage2 部分能修；用户纠偏兜底。批式走远程（qwen3-asr-rs 等）后可获益。

## 8. 背景噪声干扰 🟢 已解决

VAD threshold 敏感 + 麦克风噪声。方案：
- **能量门**（2026-08-19 已实现）：空闲（RMS < 门限 + 冷却已过）跳过 VAD/流式 NN，
  低能量噪声不再触发。
- VAD threshold 调参（0.5→0.6，代价轻声丢失）。
- 前端降噪（scout 层 RNNoise，远期）。
